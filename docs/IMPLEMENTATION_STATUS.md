## 하지 않았거나 남은 것

- 🔑 **API 키 필요**: `TAGO_API_KEY`(data.go.kr에서 4개 API 활용신청), `ODSAY_API_KEY`. 키를 넣은 뒤 다음을 확인해야 합니다.
  1. `scripts/check_providers.py`로 응답 필드명 확인 (열차·지하철 필드명은 공식 페이지에 없음)
  2. 부산·경주·포항의 TAGO 도시코드와 버스도착 지원 여부 (`/api/transit/regions`)
  3. ODsay 서버 IP 등록 (Railway 송신 IP 문제는 RAILWAY_DEPLOY.md 참고)
- 초기 후보 중 **전포 카페거리와 구룡포**는 OSM에서 확인하지 못해 좌표가 없습니다. 앱에서 직접 위치를 지정해야 합니다.
- 숙소 장소는 위시리스트에서 분류를 "숙소"로 등록한 뒤 일정의 "출발 숙소"로 고르는 방식입니다.
- 한국철도공사 운행정보 API는 어댑터를 만들지 않았습니다(TAGO로 충분).
- iOS Safari와 Android 실기기 테스트는 하지 못했습니다.
- 내일로 연령·좌석·이용 열차 규칙은 공식 문서를 확인하지 못해 넣지 않았습니다. 탑승일 수 경고만 있습니다.
- Railway에 실수로 생긴 중복 프로젝트 `our-trip`(ID 3ec2ca71…)이 있습니다. 앱은 쓰지 않습니다.

## 변경 (2026-11-18, 사용자 요청): 방 만들기 없이 지도가 메인

- 여행방 생성·초대 단계를 없앴습니다. 앱 전체가 **공유 여행 하나**(`trips.is_default`, 마이그레이션 0002)를 쓰고, 처음 접속하면 자동으로 만들어지며 초기 후보가 함께 들어갑니다.
- 첫 화면이 지도(`/`)입니다. 처음에는 지도 위 카드에서 이름을 고르거나 새 이름을 입력합니다(기기마다 한 번). 같은 이름을 고르면 같은 참여자로 들어갑니다.
- 지도를 탭하면 그 위치에 바로 장소를 추가합니다(`USER_PICKED`). "🔗 링크로 추가" 버튼은 네이버·카카오 링크 등록으로 연결됩니다.
- 하단 메뉴는 `지도 | 위시 | 교통 | 일정 | 요약`입니다.
- "둘 다 가고 싶어"는 "높은 선호도 투표가 2명 이상"으로 판정합니다.
- **보안 트레이드오프**: 이제 URL을 아는 사람은 누구나 이름을 골라 편집할 수 있습니다. `ACCESS_CODE` 환경변수를 설정하면 처음 들어올 때 입장 코드를 묻습니다(기본은 꺼짐).
  `railway variables --service web --set "ACCESS_CODE=원하는코드"`
- 기존 `/api/trips` 생성, 초대, 복구 API는 남아 있지만 화면에서는 쓰지 않습니다.
- 테스트: pytest 48개 통과, 로컬 E2E 7개 통과(지도 탭으로 장소 추가와 두 사람 투표 포함). 운영 URL은 첫 화면만 읽기 전용으로 확인했습니다(실제 공유 여행에 테스트 이름이 남지 않게).
